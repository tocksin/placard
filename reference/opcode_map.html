Cells marked ≈ work but duplicate another encoding or lack an assembler rule. Cells marked × should not be used. +1 means an operand byte follows the opcode.

Valid

  • ALU ops (LD to SUB): register, immediate or memory source into AC, X or Y, or stored to [0xNN], [x], [y,x].
  • op n, [n] (value equals address, e.g. ld 0x30, [0x30]) stores an immediate to zero page. All six ALU ops write the same byte.
  • Source 11 puts the X register on the source bus.
  • SHR uses source = AC. The assembler emits only those cells.
  • Branches with an immediate, register or memory target. JMP takes its high byte from Y.
  • Indirect branches read the target low byte from memory. Each type allows one form: jmp, bne, beq use [0xNN]; bgt, ble use [x]; blt, bra use [y,x].

Works, not assembled

  • MEM = 001 or 010 with an immediate or register source. The address mode goes unused, so it equals MEM = 000.
  • SHR with any source other than AC. The source is ignored.
  • These have no assembler rule on purpose: each repeats an assembled mnemonic. Use #d8 to emit one by hand.

Invalid

  • MEM = 101 with memory source: a zero-page read-modify-write is unsupported because the read overwrites D.
  • BGE (MEM = 101) with a memory target. The State PLD cannot fetch the zero-page address for a branch.

Classification follows State PLD rev 08, Branch PLD rev 05 and the ALU table in CPU.md. The opcode flow was checked by running every opcode through both compiled PLDs.
